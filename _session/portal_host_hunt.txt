## Conclusion
**No NEW portal API FQDN** surfaced in this hunt window.

Runtime evidence:
- Portal calls use **relative** paths in JVM heap; hostname likely resolved/stored in **native** or pinned OkHttp layer without retaining full absolute URL in dalvik-main.
- During **zap**, the only OkHttp-named host is **sfgknh.qho3cnsyil.com** (403 on portalCore from Win11 — WAF/geo, not 404 CDN).
- During **cold start**, TLS SNI shows **emowvv / sxowvd** (and CDN **34fhwevf**); probes confirm emowvv/sxowvd/dfcsq/espjey **accept** portalCore/v6/getLiveData with **portal200001** (version gate), i.e. they are portal API fronts, not new discoveries.
- getLiveDataSuccess on-device without absolute URL in heap supports **host ≠ CDN main_addr** and **host not left as cleartext** in scanned JVM regions.
